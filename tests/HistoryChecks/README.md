# Branch history checks

Run `dotnet run --project tests/HistoryChecks/HistoryChecks.csproj` from the repository root. The harness creates an isolated Git repository and preferences directory, exercises production history queries and view models, and removes its fixture afterwards. It does not interact with an existing YAGT process or a real repository.

The fixture includes 30 busy feature branches, an older release branch with a merge, a commit with a repeated subject on a different branch, a remote-only branch, a divergent upstream, and a tagged unrelated commit. Checks cover branch scope before the history limit, all-parent and first-parent traversal, selected and additional branches, fully emphasized focused history for every saved overview highlight preference, stable emphasis while inspecting commits, restoration of each overview preference, manual filters, branch updates, saved state, and migration from the previous display-mode setting.

Startup-style refresh cancellation is checked by pausing UI dispatch while several background history snapshots are queued and superseded. A first-chance exception observer verifies that these snapshots do not throw cancellation exceptions on the UI thread, and that the latest overview and focused refreshes still complete. A saved focused repository is also reopened to exercise the real startup sequence.

Add `-- --render` to open an isolated test window and save screenshots alongside the executable. This also exercises the existing advanced menu, its focused-history checkbox, disabled overview highlight choices while focused, restoration of enabled highlight choices when focus is off, enabled scope/layout/column controls, the conditional selected-branch choice, branch picker, chip removal, and horizontal overflow of many long branch names. The window is placed on verified physical Windows display 1 and does not request activation; rendering is refused if that display cannot be identified. Light/Dark themes and 100%/150% zoom are captured at wide and narrow window widths. Add `-- --list-screens` to print the available screen names without showing a window. Use `-- --keep-fixture` to retain the generated repository for inspection after a failure.
